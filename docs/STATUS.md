# Текущее состояние CombatHUD

- Действующая версия: `0.1.0`; принятое в игре поведение затемнения нижних панелей сохранено. Публичного упакованного релиза нет.
- Следующее согласованное изменение: весь управляемый HUD показывается при фактическом уменьшении HP; только HP-полоска остаётся яркой при неполном здоровье. Полная UX-семантика, включая отдельную задержку HP от полного восстановления, принадлежит [REQUIREMENTS.md](REQUIREMENTS.md).
- **Исследование 2026-10-27 выполнено; production readiness — BLOCKED.** Подробные факты, provenance, сравнение вариантов и границы доказательств: [VERIFIED_RUNTIME.md](VERIFIED_RUNTIME.md).
- Статически установлены `/Script/Genesis.GameGlobal:GetHP/GetMaxHP`: один `GenesisCharacter`, float result; штатный HUD вызывает их для player character. Подтверждена связь `GenesisCharacter.CharAttrComponent`; точный native layout компонента не установлен и для рекомендуемого getter-пути не нужен.
- Восстановлена точная slot-иерархия `HUDMainUMG_BP` → `LeftBottom_Panel` → `HUDStatusBarUMG_BP` → `CanvasPanel_0` → `Main_Panel`. HP состоит из нескольких отдельных слоёв. Предложено перенести собственное приглушение с общего левого предка на неперекрывающиеся группы детей, сохраняя native parent Visibility/opacity. Реальная доступность новых целей и отсутствие конкурирующей C++ записи ещё не проверены.
- **Механизм обнаружения выбран пользователем 2026-10-27:** сравнивать current HP в существующем номинально 50-мс цикле. Принято, что потеря и полное восстановление HP между опросами могут быть пропущены; задержка зависит от фактического update. Событийный universal hook не требуется. Runtime-привязки getters ещё не подтверждены.
- **Следующий шаг:** узкое read-only наблюдение UE4SS bindings двух HP-getters и parent-chain целевых HP-виджетов. После подтверждения — отдельный обратимый визуальный эксперимент для leaf opacity/cleanup. Отдельный read-only probe подготовлен; реальная сессия ещё ожидается.
