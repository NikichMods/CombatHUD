# Текущее состояние CombatHUD

- Действующая версия: `0.1.0`; принятое в игре поведение затемнения нижних панелей сохранено. Публичного упакованного релиза нет.
- Следующее согласованное поведение и принятый 50-мс sampled delta принадлежат [REQUIREMENTS.md](REQUIREMENTS.md). Дополнительно 2026-10-27 принято: при неполном HP постоянно видны **HP и все три быстрых предмета 1/2/3**; прочие группы остаются приглушёнными. Не распознавать лечебные предметы. Новая функция ещё не реализована и не принята в игре.
- **Runtime HP/структура: PASS, 2026-10-27.** На owning `hilda_BP_C` через UE4SS подтверждены `GameGlobal:GetHP(pawn)` и `GetMaxHP(pawn)` на CDO; `Character` ObjectProperty, float return, Lua numbers. Наблюдались `680/680 → 532.07415771484/680 → 680/680`, 577 samples, точное равенство max после лечения.
- Подтверждены восемь отдельных HP-элементов, общий `Main_Panel`, внешние родители, 12 status children и поиск соседей по точному имени/parent/address. `DamageTipList_Panel` находится локальным bounded перечислением; прямые Lua-поля внутренних панелей не требуются. У корня вложенного UserWidget `CanvasPanel_0:GetParent()` = nil — owner boundary учитывается отдельно.
- **Следующий шаг: отдельный обратимый визуальный эксперимент — READY.** Теперь он должен проверить **две постоянные яркие группы при неполном HP: HP и предметы 1/2/3**, а остальные (включая чаровиты F1/F2/F3) — приглушёнными. Проверить точные ownership/opacity-группы предметов, native final writer, визуальный результат и cleanup/rollback, сохранив штатное скрытие меню/кат-сцен. Общая production readiness остаётся BLOCKED до этого этапа и дальнейшей проверки новой policy. Никаких opacity-записей этой задачей не выполнялось.
- Первая попытка probe-01 (`ea8d36e…`) остановилась на startup pawn без HP samples; её evidence сохранён. Исправленный probe-02 (`9f1514058029aa77928faf03daf3f94ea9c7fed0`, Lua SHA256 `a4407110e1aeb95f12ba04cf906d860228b149401aafbfbfcebb1db9d0381ab6`) корректно пропустил `UIOnlyMap.DefaultPawn`, затем прочитал Хильду и автоматически остановился после восстановления HP. ## Текущий шаг: визуальный эксперимент подготовлен

Отдельный `research/opacity-experiment-01` проверяет HP + три предмета против приглушённых соседей ручными split/full режимами и полным rollback. Новое статическое item ownership установлено; live bind/labels/rendering ещё ожидаются. Перед запуском принятый CombatHUD временно отключается только в loader list, чтобы исключить двух writers; его source/installed payload и VERSION не меняются. Восстановление списка и payload hashes обязательно после закрытия игры. Процедура и границы — в README эксперимента. Визуальной приёмки или production readiness эта подготовка не означает.

### После первой opacity-сессии

Opacity-01 завершился при избыточном внутреннем item alias/name check до каких-либо записей прозрачности. Пользователь видел неизменно яркий HUD; это не визуальный провал выбранной группировки. Подтверждён только live QuickItem0/SlotIndex0 и его общий родитель; полная схема ещё не проверена. Сессия и payload сохранены, production hashes совпали. Подготовлен opacity-02 с bounded actual-tree diagnostics и адресным сопоставлением неиспользуемых внутренних aliases; outer targets и rollback не ослаблены. Нужен повторный короткий визуальный запуск. Принятый CombatHUD временно отключён только в loader list; точный исходный список будет восстановлен при закрытой игре после эксперимента.
