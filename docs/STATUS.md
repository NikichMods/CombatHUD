## Production implementation gate — 2026-10-27 (feature branch)

- **READY только для candidate/offline реализации:** owning `GenesisCharacter` и HP getters прошли live read; конечные opacity targets и отсутствие sampled native conflicts в меню подтверждены экспериментом 02, native parent `LeftBottom_Panel` исключён из записей. Пользователь согласовал отдельные timers для HP+QuickItem и остальных элементов, а также sampled damage delta.
- **Границы:** невидимая keyboard-ветка чаровитов и фактическое переключение input не приняты; смена HUD, ошибка getter, прочие меню и автоматические HP-переходы требуют последующей runtime-приёмки. Реализация не должна фиксировать alpha0 скрытой keyboard-ветки или программно делать её видимой.
- **Safety:** предсказуемое отключение при неожиданной структуре/неизвестных owner/getter, записи только в адресно проверенные 17 leaf/group targets, изменения только RenderOpacity, не Visibility/HP/gameplay. Для каждой модифицированной цели сохранять оригинал и восстанавливать лишь если текущая величина всё ещё принадлежит модификации; не перезаписывать native value при конфликте.
- **Candidate gate:** отдельная `feature/combathud-hp-visibility`, offline policy/adapter tests, `git diff --check`, identity source + SHA256. Без установки, запуска игры, изменения принятого `main` и объявления версии принятой до пользовательской проверки.

## Feature prototype / offline verification

- `Scripts/policy.lua`: два независимых alpha/timer состояния; HP delta раскрывает обе группы сразу, неполное HP удерживает HP+quick items в полной яркости, полное восстановление запускает только их собственную задержку. Неоднозначные/невалидные значения сбрасывают состояние к полной яркости. Первые замеры после смены pawn, изменения max HP или отката игрового времени не трактуются как событие урона.
- `Scripts/main.lua`: адресная проверка HUD → персонаж → widgets, bounded enumeration 17 disjoint targets; `LeftBottom_Panel` и нативные menu/visibility ancestors не изменяются. `CrystalList_Panel` с native alpha0/Hidden не трогается, при реальном открытии возможно adoption нативного ненулевого alpha; это поведение **ещё не наблюдалось в игре**. Альтернативная pad-группа управляется по проверенной topology.
- В цикле меняется только `RenderOpacity` targets при необходимости; при изменении значения нативным writer прекращаются дальнейшие записи и восстанавливаются только значения, всё ещё совпадающие с последними записями мода. При исчезновении HUD/неподходящем pawn восстанавливается базовая прозрачность без чтения HP постороннего объекта.
- **OFFLINE PASS:** `python tools/test.py` (все моды) с `lupa==2.8`; покрыты таймеры, повреждение/лечение, первый partial HP, повторный урон, бой, смена HUD и pawn, нативное меню, native conflict, ошибка getter, пауза и откат времени. `git diff --check` пройден. Это подтверждает Lua-policy и mock-интеграцию, **не** загрузку в UE4SS и не визуальный результат.
- **Следующий gate:** оформить нумерованный, хешированный и неизменяемый кандидат из точного commit; проверить установку при закрытой игре; провести пользовательский runtime-тест (полное/неполное HP, урон от окружения, предметы 1/2/3, задержки, бой, меню). Чаровиты не входят в обязательный немедленный тест по принятому решению: их реальная видимость остаётся явно отсроченной.
