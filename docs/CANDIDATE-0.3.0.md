# CombatHUD 0.3.0 — экспериментальный кандидат, НЕ принят

**Ветка:** `feature/contextual-hud-reveal`. **Стабильная версия:** 0.2.0 в `main`, неизменна.
**Статус:** источник и офлайн-проверки; игровая установка, запуск, визуальная оценка и приемка ещё не выполнены.

## Что проверять

1. В безопасном месте вне боя с полным HP дождаться приглушения до 20%; нажать текущую игровую кнопку «Взаимодействовать» **без доступного объекта**. Весь управляемый HUD должен немедленно стать ярким, продержаться 1,5 с и за 1 с вновь приглушиться. Повторное нажатие обновляет отсчёт.
2. Удерживать текущий модификатор боевых навыков на геймпаде: яркими должны стать **только правые две skill-группы**, остальные — остаться приглушёнными. После отпускания только эти группы плавно возвращаются к текущей базовой непрозрачности за 1 с без дополнительной паузы.
3. Проверить комбинации: бой, урон вне боя, неполное HP, исцеление, нажатие взаимодействия во время fade и удержание навыков во время общего раскрытия. Существующие HP и три быстрых предмета всегда сохраняют приоритет.
4. Открыть обычное меню и выполнить подтверждение, закрыть меню, сменить геймпад/клавиатуру. HUD не должен насильно проявляться в нативно скрытом состоянии или оставаться ярким после выхода из меню из-за пропущенного отпускания.
5. При возможности проверить смену назначения Interact в игровом интерфейсе и возврат назад, включая совпадение физической кнопки с подтверждением в меню. Этот сценарий **не имел runtime proof** в observer03; если проверить нельзя, оставить отдельным непроверенным пунктом.
6. Закрыть игру штатно; проверить UE4SS.log, loader/state, точные installed source hashes и отсутствие ошибки/переполнения логов. Чаровиты до естественного открытия отдельно не исследовать.

## Пределы текущего механизма

- Input-source подтверждён observer03 на Steam 1.09/build12996889, UE4SS83330635, PC mapping namespace `K-Interact` и `PC-Joystick-Interact`. Другие платформенные namespaces/chords не заявлены как поддерживаемые.
- Натуральное held-state `GetModifier_SpecialSkill()` подтверждено observer02. Структура правых root widgets известна; четыре skill-слота и два декоративных Image не доказывают наличие шести видимых навыков.
- Интеграция использует native pressed hook лишь для пробуждения и `WasInputKeyJustPressed` на актуальном FKey. Есть pre/post Scene, HUD owner и native ancestor guards; fan-out дедуплицируется временем кадра.
- Последствия изменения фокуса, удержания при смене устройства/меню и конфликты с другими UI-модами должны оцениваться по реальной игре. Если optional input source не проходит проверку, сохранять штатную автоматическую прозрачность 0.2.0; никаких фиксированных кнопок-fallback.
- До игровой проверки **никаких утверждений о runtime PASS, принятой версии или стабильном релизе**.

## Подготовка локальной передачи

Codex должен получить точный commit SHA ветки и проверить соответствие рабочих исходников этому SHA. Только при закрытой игре и после verified rollback вне loader-path подготовить установку отдельного тестового 0.3.0. Не заменять установленный 0.2.0, пока игра запущена; не запускать/завершать игру и не использовать hot reload самостоятельно. После теста сверить installed hashes и сохранить обычный log snapshot. Для финальной оценки пользователь сообщает, как выглядел HUD в сценариях выше.
